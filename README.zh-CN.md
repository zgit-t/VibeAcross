# VibeAcross

[English](./README.md) | **简体中文**

VibeAcross 是一款**本地优先的桌面工作区管理工具**，面向使用 AI 编程工具进行「Vibe Coding」的开发者，用于统一管理本地开发项目、本机已安装的 AI 编程工具、开发任务与工作上下文。

所有数据都**保存在本机**的 SQLite 数据库中。没有远程服务器、没有账号、没有云同步，也不内置大模型 API。

> **状态：** 正式版（`v1.0.0`）。暂未发布预编译安装包，请从源码构建（见[安装](#安装)）。

## 为什么需要 VibeAcross

当你同时使用多个 AI 编程工具——终端代理、IDE 助手、桌面应用——每个工具都各自维护自己的项目、任务与历史记录。切换工具时，往往要重新找到正确的目录、工具和上下文。

VibeAcross 提供一个统一的本地中枢，可以：

- 检测本机已安装的 AI 编程工具。
- 登记本地项目目录，并记住每个项目的默认工具。
- 按项目跟踪开发任务。
- 保存**工作上下文**（项目 + 工具 + 任务），以便随时重新打开。
- 在工具确实提供受支持机制时，创建 / 列出 / 恢复 / 重命名**原生 AI 会话**，并如实标注哪些能力**不支持**或**尚未核实**。

### 设计原则

- **本地优先**：无远程服务器、无账号、无云同步、无遥测、不调用大模型 API。
- **能力诚实**：绝不虚构命令行参数或 API。未经确认的能力一律标注为「尚未核实」，而不是当作可用功能。
- **安全启动**：以结构化参数数组与明确的工作目录启动工具，绝不拼接 shell 字符串。
- **不静默操作**：不会静默切换工具、静默新建会话，也不会在未经同意时删除原生对话。

## 核心功能

- **项目管理**：导入本地项目目录，设置名称与备注、默认工具，可在系统文件管理器中打开目录或复制路径。
- **项目健康检查**：检查项目目录是否仍然存在、默认工具是否就绪，并可在目录被移动后重新定位（不触碰任何源代码）。
- **AI 工具检测与配置**：通过 `PATH`、常见安装目录、Windows 卸载注册表项与快捷方式检测六款内置工具；自动检测不可靠时可手动添加或配置工具。
- **任务**：按项目创建任务，包含标题、描述、状态、优先级与截止日期。
- **工作上下文（Sessions 页面）**：保存「项目 + 工具 + 任务」组合并在之后恢复。Level 1 恢复会重新打开项目目录与所选工具。
- **原生 AI 会话**：在项目详情中为支持的工具创建 / 列出 / 恢复 / 重命名会话，界面中显示每个工具的能力矩阵。
- **全局搜索**：用 `Ctrl/Cmd + K` 打开只读搜索，检索项目名称/备注、任务标题/描述与工作上下文名称。**不会**索引或扫描项目源代码。
- **备份与恢复**：创建单文件、自包含的数据库备份（`.vibeacross-backup`）并从备份恢复；恢复前会自动保留一份保护性备份。
- **主题与语言**：浅色 / 深色 / 跟随系统主题，以及简体中文（zh-CN）/ 英文（en-US）界面。

## 支持的 AI 编程工具

VibeAcross 内置六款工具的定义。检测与配置对全部工具都可用；**原生会话操作取决于工具是否提供真实且经核实的机制**，因此各工具不同。

| 工具 | 类型 | 启动项目 | 创建会话 | 列出会话 | 恢复会话 | 重命名会话 |
| --- | --- | --- | --- | --- | --- | --- |
| **OpenCode** | CLI | ✅ | ✅ | ✅ | ✅ | ✅ |
| **Claude Code** | CLI | ✅ | ✅ | ❌ | ✅ | ❌ |
| **OpenAI Codex CLI** | CLI | ✅ | ⚠️ 尚未核实 | ⚠️ 尚未核实 | ⚠️ 尚未核实 | ⚠️ 尚未核实 |
| **Cursor** | 桌面 | ✅ | ❌ | ❌ | ❌ | ❌ |
| **Trae** | 桌面 | ✅ | ❌ | ❌ | ❌ | ❌ |
| **WorkBuddy** | 桌面 | ✅ * | ❌ | ❌ | ❌ | ❌ |

图例：✅ 支持且已在 Windows 上核实 · ❌ 工具本身不支持 · ⚠️ 工具的官方 CLI 支持，但**本机尚未核实**。

说明：

- **启动项目**指以该工具打开项目目录：CLI 工具以项目为工作目录启动；Cursor 与 Trae 直接以目录参数打开项目。对于 **WorkBuddy** 的 `*`，应用仅以项目为工作目录启动，官方未提供公开的「打开该目录」参数，因此需在 WorkBuddy 内自行选择工作目录。
- **OpenCode** 的原生会话已端到端核实：创建 / 列出 / 恢复 / 重命名。
- **Claude Code** 支持 `claude --session-id <uuid>` 创建、`claude --resume <id>` 恢复（已核实）；官方未提供机器可读的历史枚举，也不支持对既有会话重命名。
- **Cursor / Trae / WorkBuddy** 为桌面应用，无公开 CLI 会话接口，因此不提供原生会话操作。
- 仅读取**会话元数据**（ID、标题、目录、时间戳）。VibeAcross 绝不读取或保存对话内容，也绝不读取或修改任何工具的私有数据库。
- 可在 Tools 页面添加自定义工具；除非确认了机制，其原生会话支持一律标注为「尚未核实」。

## 系统要求

**运行已构建的应用：**

- Windows 10 或 Windows 11（x64）。
- Microsoft Edge WebView2 运行时——Windows 11 已预装；多数已更新的 Windows 10 也有（否则请从 Microsoft 官网安装）。

**从源码构建还需：**

- Node.js 20 及以上（建议 22+）与 npm。
- Rust（stable，最低 1.77.2），使用默认的 `x86_64-pc-windows-msvc` 工具链。
- Microsoft C++ Build Tools，含「使用 C++ 的桌面开发」工作负载（Rust 在 Windows 上的链接器）。

VibeAcross 目前**仅支持 Windows**。工具检测依赖 Windows 注册表与快捷方式。

## 安装

暂时没有发布二进制文件，请从源码构建。

```bash
# 1. 克隆仓库
git clone https://github.com/zgit-t/VibeAcross.git
cd VibeAcross

# 2. 安装前端依赖
npm install

# 3. 构建桌面应用与安装包
npm run tauri:build
```

构建产物（`src-tauri/target/release/`）：

- 可运行程序：`vibeacross.exe`
- 安装包位于 `src-tauri/target/release/bundle/`：
  - `msi/VibeAcross_1.0.0_x64_zh-CN.msi`
  - `nsis/VibeAcross_1.0.0_x64-setup.exe`

安装包只包含运行所需内容，不包含源代码、开发数据库或临时文件。安装与卸载都不会影响 `%APPDATA%\com.vibeacross.app` 中的用户数据。

如需以开发模式运行而非打包，请见[开发](#开发)。

## 首次启动

1. 启动 VibeAcross。首次运行会自动创建本地 SQLite 数据库（见[我的数据在哪里？](#我的数据在哪里)）。
2. 打开 **Tools**，查看本机检测到六款内置工具中的哪些。若某工具缺失或检测不可靠，点击 **Add tool**，提供其可执行文件路径或命令名。
3. 可选：打开 **Settings** 设置界面语言、主题、默认项目目录与默认开发工具。

VibeAcross 内部无需为任何 AI 工具配置账号或 API Key——它只启动你已经安装并登录的工具。

## 使用方法

### 创建项目

1. 进入 **Projects** → **Add project**。
2. 选择本地目录，可选设置名称、备注与默认工具，然后保存。
3. 打开项目详情，可查看路径、健康状态、任务与原生会话。

### 检查与修复项目

- 在 **Project health** 区块点击 **Recheck**，验证目录与默认工具。
- 若目录被移动，使用 **Relocate** 指向新位置。VibeAcross 只更新自身记录，绝不移动、复制或删除你的源代码。

### 启动工具

- 在项目详情中选择工具并点击 **Launch**。CLI 工具在项目目录中打开；桌面工具则正常启动。
- 只有在工具已检测/配置、且项目目录有效时才能启动。

### 创建与恢复原生会话

1. 在项目详情中打开 **Run session** 区块。
2. 选择工具。会话列表会针对该工具重新加载，并显示该工具的原生会话能力（创建 / 列出 / 恢复 / 重命名）为「支持 / 不支持 / 尚未核实」。
3. **Create & open** 新建原生会话（仅在「创建」受支持时可用）。
4. **Continue session** 以原生方式恢复列表中的会话。
5. **Rename** 修改 VibeAcross 中保存的显示名称；在受支持时也可选择同步重命名工具内的标题。重命名绝不改变原生会话 ID。
6. **Delete local record** 只删除 VibeAcross 的记录，不删除原生对话。

### 任务

进入 **Tasks** 创建与编辑任务（标题、描述、状态、优先级、截止日期）。任务始终关联一个项目。

### 工作上下文（Sessions 页面）

**Sessions** 页面列出已保存的**工作上下文**（项目 + 工具 + 任务）。可恢复某个上下文，以重新打开项目目录与所选工具。若希望在启动时于概览页显示最近上下文，请在 Settings 中开启「启动时显示最近的工作上下文」；「启动时自动恢复」是独立的选项，默认关闭。

### 搜索

按 `Ctrl/Cmd + K`（或使用侧边栏搜索入口）打开全局搜索，检索项目、任务与工作上下文。结果按分组展示并支持键盘导航。

## 配置

打开 **Settings** 可修改：

- **界面语言**：简体中文（zh-CN）或英文（en-US）。
- **主题**：浅色 / 深色 / 跟随系统。
- **默认项目目录**：创建项目时的起始位置。
- **默认开发工具**：打开项目时的首选工具。
- **恢复**：启动时显示最近工作上下文，并可选在启动时自动恢复。
- **数据备份与恢复**：创建与恢复数据库备份。
- **数据目录**：查看数据库存储位置。

## 常见问题

### 我的数据在哪里？

本地 SQLite 数据库：`%APPDATA%\com.vibeacross.app\vibeacross.db`。数据库结构由 `src-tauri/migrations/` 下的迁移脚本管理，版本记录在 `PRAGMA user_version`。如需重置，请关闭应用后删除该目录下的 `vibeacross.db*` 文件。

### VibeAcross 会把数据发送到别处吗？

不会。没有远程服务器、账号、云同步、遥测或大模型 API。工具检测完全在本机完成，从不上传路径或环境变量。

### 需要预先安装 AI 工具吗？

启动工具与原生会话需要已安装对应工具——VibeAcross 检测并启动你已安装的工具。也可以按路径或命令名手动登记自定义工具。

### 为什么某工具显示「尚未核实」？

因为其官方机制在本机无法确认。VibeAcross 宁可如实展示，也不猜测参数来提供未经核实的功能。

### VibeAcross 会自动帮我切换工具吗？

不会。它绝不静默切换工具或新建会话，工具始终由你选择。

### 备份会包含我的源代码吗？

不会。备份只包含应用数据库（项目、任务、工具配置、工作上下文、设置），不含源文件、令牌或密码。

### 为什么看不到某个功能？

凡未在[核心功能](#核心功能)与[支持的 AI 编程工具](#支持的-ai-编程工具)中列出的功能即为尚未实现。应用不提供占位数据或演示数据。

## 已知限制

- **仅支持 Windows**（Windows 10/11，x64）。
- **暂未发布预编译版本**，需从源码构建。
- **各工具的会话支持不同**。只有 OpenCode 具备完整的原生会话支持；Claude Code 支持创建/恢复，但不支持历史枚举与重命名；Codex CLI 由其官方 CLI 支持，但本机尚未核实；桌面工具（Cursor、Trae、WorkBuddy）无 CLI 会话接口。
- **WorkBuddy** 仅以项目为工作目录启动——不存在公开的「打开该目录」参数，目录选择需在应用内完成，且工作上下文自动打开对它不可用。
- 只处理**会话元数据**，绝不读取或保存对话内容，也不读取或修改任何工具的私有数据库。
- **无云同步或自动定时备份**。备份/恢复为手动、单文件操作；恢复后界面会自动重新加载。
- **尚未在打包后的应用中进行点击验证**；覆盖方式为类型检查、生产构建、单元/组件测试与后端集成测试。

## 开发

### 前置条件

见[系统要求](#系统要求)。安装 Node.js 20+、Rust（stable，≥ 1.77.2）与 Microsoft C++ Build Tools。验证：

```powershell
node --version
rustc --version
cargo --version
```

### 安装与运行

```bash
npm install

# 仅浏览器预览前端（无 Rust 后端）
npm run dev

# 启动完整桌面开发窗口（需 Rust）
npm run tauri:dev
```

`tauri:dev` 会先执行 `npm run dev`（Vite，端口 1420），再在桌面窗口中加载。

### 常用命令

| 命令 | 说明 |
| --- | --- |
| `npm run dev` | 启动 Vite 开发服务器（浏览器模式） |
| `npm run build` | 类型检查并构建前端生产版本 |
| `npm run preview` | 预览前端生产构建 |
| `npm run typecheck` | TypeScript 严格类型检查 |
| `npm run test` | 前端单元测试（Vitest + Testing Library） |
| `npm run test:watch` | 前端测试监听模式 |
| `npm run tauri:dev` | 启动 Tauri 桌面开发窗口 |
| `npm run tauri:build` | 构建 Tauri 桌面应用与安装包 |

后端（在 `src-tauri/` 目录下执行）：

```bash
cargo check      # 编译检查
cargo test       # 集成测试（迁移、项目、工具、会话等）
cargo clippy     # 代码检查
```

### 目录结构

- `src/` — React + TypeScript 前端（`pages/`、`components/`、`features/`、`services/`、`types/`、`i18n/`）。
- `src-tauri/` — Rust 后端与 Tauri 配置（`src/`、`migrations/`、`tauri.conf.json`）。
- `public/`、`index.html` — Vite 入口资源。

### 开发约定（摘要）

- TypeScript 严格模式；不得为消除报错而关闭类型检查。
- 业务数据仅通过 `src/services/` 调用 Rust 后端读写；前端不得直接访问 SQLite。
- 样式引用 `src/styles/tokens.css` 的设计令牌，组件使用 CSS Modules；不引入额外样式框架。
- 工具启动一律经由受控的 Rust 后端，使用结构化参数，绝不拼接 shell 字符串。
- 新增结构时**追加**新的迁移文件，不修改历史迁移。

### 开发期间的本地数据

运行时数据库会自动创建于 `%APPDATA%\com.vibeacross.app\vibeacross.db`。SQLite 数据库与运行数据均已被 gitignore，绝不可提交。
